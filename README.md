# NAS Compress Backup

在 NAS 上按任务分批加密归档，通过 CloudDrive2 直接上传百度网盘。React、Lucide React 和 daisyUI 界面，Python/FastAPI 与 SQLite 后端。

## 功能

- 仅管理密码登录，无需用户名；已有版本升级后沿用原密码。
- 多个独立任务，目录选择器可浏览只读接入的 `/volume1` 和 `/volume2`。
- 创建任务后先扫描，展示新增、修改、移动、源已删除和小文本逐行差异，由用户开始首次备份。
- 运行支持暂停、继续和结束本次；结束时保留已提交备份，释放未提交工作副本。移除本地任务记录不会删除NAS来源或云端备份。
- 每任务独立设置增量间隔（1至3650天，默认7天），每次备份结束后重新计时；开启夜间限制时到期后等待夜间窗口，关闭夜间限制后全天按周期自动运行。服务停机期间错过的周期只补跑一次。夜间时段在设置里填写，到点不开始新包，允许当前工作和已开始的上传收尾。手动运行可绕过时段，暂停和每任务自动备份开关仍单独生效。
- 工作数据默认上限128GB，按恢复组预留空间，不先压完整个来源目录；大文件有界分段。
- 按后缀选择压缩级别，7z AES-256内容及文件名加密。每个任务可使用默认归档密码或单独密码，已有归档后锁定。每个上传对象不超过3,900,000,000字节。
- 外置PAR2保护数据包与加密组清单，恢复块按最大成员计算；组内其他文件和冗余完好时，可恢复一个完整缺失成员。
- 逐包上传；任务完成、云端数量与大小匹配后，更新当前索引并回收本地工作副本。
- 一个路径只维护当前成功副本。NAS上删除源文件时，保留网盘副本；不提供备份点或历史版本。
- Bark只提醒重试耗尽等需要处理的异常，同类异常24小时内去重。正常完成不推送。

扫描阶段总量未知时显示活动进度、当前目录和已扫描文件数；后续分别显示读取、打包、冗余、上传及大小核对进度，百分比细化到一位小数，同时显示已处理字节与总量。源数据封包/复用按字节统计，大文件分段完成即可看到进展；已处理文件数与已确认恢复组分别展示。上传总量随新包生成增加，不代表全部来源数据的总量。小文本基线只在本地保留当前内容，单文件上限512KB、全局缓存上限128MB，不为对比下载云端文件。

文件变化与备份文件页面优先使用本地SQLite保存的当前云端备份清单，日常打开页面和扫描不会重新下载清单或云端原文件。点击“刷新云端清单”才查询云端组目录里的文件名和大小，检查包是否缺失，并记录确认时间；缺失后重新扫描可安排补传。压缩包里的原始路径来自保存的加密索引映射，不能从压缩包名称推断。没有本地文本基线时只展示文件变化信息。

**上传确认只比较数量和字节数，不会下载回读，也不等于远端内容的SHA-256验证。** 本地仍计算文件哈希、检查压缩包和PAR2。

## 安装

目前提供 Linux amd64 镜像，适合 x86-64 群晖。镜像由本仓库 GitHub Actions 测试、构建并发布：

```text
ghcr.io/ccawmiku/nas-compress-backup:0.2.5
```

1. 先运行官方 CloudDrive2 并连接百度网盘。将 `/volume1/暂时上传` 映射到 CloudDrive2 的 `/upload:ro`。
2. 下载本仓库 `compose.yaml`，按实际卷位置修改状态/工作目录。
3. 创建来源挂载、数据和工作目录后，在 Container Manager 导入项目启动。
4. 在局域网打开 `http://NAS-IP:19800`，设置自己的管理密码。
5. 设置 CloudDrive2 地址（桥接网络使用NAS的局域网IP及19798端口，不能使用127.0.0.1）和API令牌，点击“保存并测试连接”；设置归档密码、Bark和运行时段。需要全天运行时关闭“仅在夜间时段自动运行”。
6. 新建任务并设置增量间隔，查看扫描结果后点击“立即运行”。默认云端总目录“群晖压缩备份”。

配置和令牌保存在持久化数据目录，API不返回明文令牌或密码。真实凭据不要写入Compose或提交Git。可选的私有引导文件格式如下，放在仓库外并以只读方式挂载到 `/run/secrets/bootstrap.json`：

```json
{
  "clouddrive_token": "YOUR_PRIVATE_API_TOKEN",
  "archive_password": "YOUR_ARCHIVE_PASSWORD",
  "bark_url": "YOUR_PRIVATE_BARK_URL"
}
```

引导文件只补充尚未配置的值，不覆盖现有设置。首次备份前可以设置归档密码；有归档后第一版锁定密码，避免已有数据无法解密。

## 存储结构

```text
群晖压缩备份/
  任务名称_固定ID/
    groups/组ID/       数据包、加密文件清单、PAR2和提交记录
    catalog-a/         当前索引的两个交替写入槽之一
    catalog-b/         用于中断时保留一个可读索引
```

两个索引槽用于提交中断后的对账，不作为用户历史版本功能。选择有效且代次最高的目录，检查槽内的 `catalog-代次-ID.json` 提交凭据，确认其中列出的索引对象齐全、大小及SHA-256匹配，再解密对应的 `current-index-代次-ID.7z` 得到 `current-index.json`（旧版使用 `catalog.json` 和 `current-index.7z`）；它包含原始路径、包内路径、分段顺序和SHA-256。来源删除后保留的条目会标记 `present: 0`。

多文件共享压缩包，多个包共享PAR2。组内还有当前有效内容时保留整组，混合包中的过时字节不会为了整理而自动重压；因此取消历史功能也不意味着每次修改都会立即释放旧包的全部空间。

临时空间配额覆盖本程序数据工作区，数据库/日志另计；现有CloudDrive2自己的缓存由CloudDrive2配置控制。系统余量不足时等待。源文件持续变化会暂缓处理；应用数据库等活跃数据需要合适的一致性备份方式。

## 取回当前文件

网页“备份文件 → 查看位置”可查看和下载所需数据包及PAR2。缺失包先在其组目录运行 `par2 repair recovery.par2`。

下载对应任务的索引和数据组，解密索引后可使用附带工具按分段重建一个文件：

```bash
python scripts/restore_file.py \
  --index /path/to/current-index.json \
  --archives /path/to/downloaded-task-directory \
  --path '/original/source/file.mp4' \
  --output /path/to/new-destination/file.mp4 \
  --password-file /path/to/private-password-file
```

工具不会覆盖已存在的目标文件；完成后检查分段和整文件SHA-256。无需原NAS数据库，也不需要管理网页在线。

## 开发和测试

Python 3.12+、Node.js 24，以及 `7zz`、`par2`。

```bash
pip install -r requirements.txt
python scripts/generate_proto.py
pytest -q
cd frontend
npm ci
npm run build
```

前端开发使用 `npm run dev`；后端使用 `uvicorn app.main:app --host 127.0.0.1 --port 19880`。设置 `NCB_DATA`、`NCB_WORK`、`NCB_OUT` 和 `NCB_ROOTS` 指向隔离测试目录。

GitHub Actions 在 Linux 上运行真实分段归档、增量更新和完整缺失对象PAR2修复测试，通过后构建并推送镜像。7-Zip二进制与CloudDrive2 API定义都校验固定SHA-256；官方API定义变更时应人工核对并更新固定值。

管理员密码遗忘时，在NAS本机执行 `docker exec nas-compress-backup python -m app.admin reset`，随后在内网页面重新设置管理密码。此操作保留任务和归档数据。


## 0.2 更新与性能

沿用原数据目录升级，无需删除任务或重设密码。旧任务的间隔默认为7天，可逐任务编辑；周期编辑不会清除已完成状态，手动扫描不会改变下次到期时间，手动备份结束会重新计时。未完成首次备份的任务不会自动启动。

页面可见且有任务运行时每3秒刷新，空闲时每15秒刷新，隐藏时暂停概览查询，避免重叠轮询。概览统计有3秒活动缓存/30秒空闲缓存，空间显示缓存5秒；实际打包的配额检查始终重新计算。扫描仅查询必要元数据并减少逐文件路径解析，内容复用查询增加数据库索引。


0.2.1 修复：排队时清除旧阶段进度并显示正在等待的任务；刚完成的手动扫描在5分钟内可复用，读取和打包仍检查文件变化；同一运行暂停继续不重复扫描，升级时保留旧运行的分段状态。

0.2.2：每包文件数量上限4096，候选准备及打包读取批次同步扩大；原始数据每包上限3,700,000,000字节，上传对象上限3,900,000,000字节。打包候选不批量载入文本基线，避免大量小文本占用过多内存。

0.2.3：SQLite事务保留未提交修改的旧记录，对外只展示已提交索引；云端索引和提交凭据使用唯一名称，凭据最后上传；写前保存提交意图，重启先完成同一次提交对账；只有确认后才同时切换本地索引、提交组状态并回收工作文件。取消未提交的修改会还原旧记录；待对账的提交不能直接丢弃。压缩包及冗余在登记可上传之前执行fsync，SQLite显式使用FULL同步。云端确认仍只核对大小，不自动下载原文件。网页时间固定为北京时间，并提示全局自动调度关闭状态。

0.2.4：修复未执行任务暂停后一直显示收尾中；暂停且没有活跃工作或待对账提交的任务可以安全移除本地记录，源与云端副本保留。目录选择器增加同目录多选和全选。每包只遍历一次工作区核对空间，哈希结果每32个提交一次并限制进度写入频率；中断最多重读尚未提交的小批次。7z压缩字典按级别限制为1/8MiB，PAR2单线程、96MiB工作预算，目标源块数从4096调整到256，恢复块仍按最大成员向上取整并加余量，保持整文件缺失保护。这些是子进程工作参数，不等于整个容器的内存上限。阶段耗时会写入日志；CI使用20MiB合成数据比较冗余耗时和子进程峰值RSS，并删除一个完整数据文件验证修复。

0.2.5：关闭夜间限制改为全天按任务周期自动运行，运行中的自动任务也不再等待夜间窗口；暂停、任务自动备份开关和首次手动开始规则保留。进度显示一位小数、字节进度、当前上传对象与恢复组，修正小包总量和阶段切换时残留旧进度。冗余计划的块大小改用MB（一位小数，十进制）；计算仍使用原始字节值。登录页、导航和浏览器标签使用自定义SVG标志。
